# Local benchmark result convention

The native CPU runner (`run_cpu.py`) creates a UTC timestamped directory with
`manifest.json`, `results.json`, `REPORT.md`, logs and `checksums.json`. Each
`<workload>-<VUs>vu-<repetition>/` child contains `run.json`, compressed `raw.json.gz`,
metrics-only `summary.json`, `resources.csv` and seed evidence when applicable.
An incomplete run remains labelled `incomplete`; inspect logs rather than treating
missing metrics as zero. Every row represents one repetition, not an average of
percentiles across repetitions. Keep the whole directory when sharing results.

`gdrn-cpu-source.zip` is a source upload bundle generated by
`package_cpu_source.py`, not measurement evidence. Kaggle Output exports the
separate `gdrn-cpu-results.zip`. Both are ignored by Git.

## PowerShell/Docker runner

Each `run-reporting-benchmark.ps1` invocation creates a timestamped directory
containing:

- `run.json`: commit, workload, VUs, durations, dataset/seed and start/end;
- `raw.json`: k6 raw samples;
- `summary.json`: k6 summary with throughput, latency percentiles and error rate;
- `seed.json`: dataset distribution and seed outcome when `-SeedData` is used;
- `docker-stats.csv`: optional CPU/RAM samples when `-CollectDockerStats` is used.

Result data is intentionally ignored by Git because it is machine-specific and
can be large. Preserve the directory as an external D3 evidence artifact and
reference its path/checksum in the handoff. The runner removes the short-lived
setup JWT from `summary.json` before saving it; do not retain raw outputs from a
custom invocation unless they have been checked for credentials.
