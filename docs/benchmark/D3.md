# D3 benchmark contract and evidence

## Scope

D3 owns `benchmark/` and `docs/benchmark/`. The current artifact measures the
implemented reporting contracts only:

| Workload | Contract | Query mix |
| --- | --- | --- |
| `write` | E07 `POST /api/reports` | 100% report creation |
| `read-page` | E08 `GET /api/reports` | page/size/sort, stable descending creation order |
| `read-radius` | E08 `GET /api/reports` | page/size/sort plus `lat`, `lon`, `radiusMeters` |
| `mixed` | E07 + E08 | 20% write, 60% page read, 20% radius read |

The workload calls no endpoint that is absent from the current OpenAPI contracts.
The seed script uses E07 itself and therefore is not an application seed endpoint.

## Reproduction record

For every repetition, preserve the timestamped directory under `benchmark/results/`
and record:

- Git commit and UTC start/end;
- dataset size, deterministic seed and 70% dense / 30% wide spatial distribution;
- report-type mix, page size/count, radius and workload mix;
- VUs, warm-up, steady duration, ramp-down and repetition count;
- reset and seed method on a disposable PostGIS database;
- k6 version, generator version, server/database topology and host configuration;
- throughput, average/p50/p95/p99 latency, error rate, and CPU/RAM when sampled;
- limitations and any load-level change justified by evidence.

JWT setup is part of the reproducibility contract. The k6 setup login reads the
credential from environment variables and rejects a run whose complete planned
window can exceed the token lifetime (current contract: 900 seconds). Expired
token failures are not treated as a domain bottleneck.

## Acceptance status

The scripts and Kaggle preflight notebook are prepared on the D3 branch. A local
run is a baseline for this machine; it becomes an official Phase 1 measurement only
after the X1 integration gate is complete on the measured stable commit. Kaggle is
not complete unless the notebook verifies the required runtime and the benchmark
server/database are explicitly available.

No performance benefit is claimed. Redis, a read replica, a queue, a broker or any
other Phase 2 candidate remains a hypothesis to be tested only after an observed
bottleneck and an approved design; none is implemented here.
