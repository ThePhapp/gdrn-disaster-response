# A2 — Docker giao diện, CI và cách chạy thống nhất

**Nhánh:** `feat/x2-a2-browser-ci`<br>
**Nền:** `main` tại `761e6f5`<br>
**Trạng thái:** HOÀN TẤT trên nhánh, chờ review/merge; remote GitHub CI chưa chạy vì nhánh chưa đẩy mã.

## Môi trường chạy đã triển khai

- `frontend/Dockerfile` dùng multi-stage `node:22.14.0-alpine` để chạy `npm ci` và
  `npm run build`, sau đó phục vụ tệp kết quả bằng `nginx:1.27-alpine`.
- `frontend/nginx.conf` phục vụ `/login` và deep định tuyến bằng SPA history phương án dự phòng;
  `/api` proxy tới `backend:8080` trong mạng Compose. Trình duyệt chỉ dùng URL tương đối
  `/api`, không thấy hostname container.
- Compose có `database`, `backend`, `frontend`; named volume `database-data` vẫn được
  giữ. Giao diện chờ ứng dụng phía máy chủ sẵn sàng, ứng dụng phía máy chủ chờ cơ sở dữ liệu sẵn sàng. `FRONTEND_PORT`
  mặc định `5173` và có thể đổi riêng trong `.env`; `APP_PORT`/`DB_PORT` giữ nguyên.
- Public `VITE_*` bản đồ cấu hình chỉ đi qua biên dịch args nếu người dùng cấu hình; JWT,
  cơ sở dữ liệu password và DEMO thông tin xác thực chỉ ở ứng dụng phía máy chủ environment, không copy `.env`
  vào giao diện biên dịch context.
- `scripts/local.ps1` vẫn chạy Vite máy chủ cho dev và đọc `FRONTEND_PORT`; `scripts/dev.ps1`
  chạy đầy đủ Compose và kiểm tra nhanh health/API/frontend.

## CI hiện có

`.github/workflows/ci.yml` giữ các kiểm tra ứng dụng phía máy chủ `bash ./mvnw clean verify` với Docker/Testcontainers,
giao diện `npm ci`/typecheck/test/build, Compose cấu hình kiểm tra dữ liệu và Compose ảnh môi trường biên dịch.
Tác vụ `browser-e2e` tạo bí mật kiểm thử tạm, chạy Compose với database/API/frontend thật,
chạy kiểm tra nhanh gateway và Playwright Chromium qua Nginx `/api`, tải lên diagnostics khi lỗi,
sau đó dừng container bằng `docker compose down` và xóa `.env` tạm. Không dùng `down -v`.

Rà soát bổ sung giữ Maven Wrapper làm bộ công cụ biên dịch duy nhất trong CI. Lệnh
`dev.ps1 smoke -BaseUrl ...` chỉ kiểm tra ứng dụng phía máy chủ chạy trên máy chủ như hướng dẫn vận hành mô tả;
kiểm tra nhanh không truyền `BaseUrl` vẫn kiểm tra đầy đủ ứng dụng phía máy chủ, giao diện SPA và Nginx
`/api` proxy của Compose.

## Cách chạy sau clone

```powershell
.\scripts\dev.ps1 init
.\scripts\dev.ps1 up
.\scripts\dev.ps1 smoke
```

Mặc định mở `http://127.0.0.1:5173/login`, ứng dụng phía máy chủ sức khỏe ở
`http://127.0.0.1:8080/actuator/health`, Swagger ở
`http://127.0.0.1:8080/swagger-ui/index.html`. Cách phát triển nhanh bằng Vite máy chủ
vẫn dùng `scripts/local.ps1 -Action setup/start`; không dùng `docker compose down -v`
để làm mất cơ sở dữ liệu volume. Hướng dẫn đầy đủ đã cập nhật tại README,
`docs/HUONG_DAN_CAI_DAT_VA_CHAY.md` và `docs/P01_LOCAL.md`.

## Bằng chứng thực tế

- `docker compose --env-file .env.example config --quiet`: ĐẠT.
- `docker compose --env-file .env.example build frontend`: ĐẠT; Docker chạy
  `npm ci` và môi trường triển khai biên dịch trong ảnh môi trường.
- `docker compose --env-file .env up --build -d --wait --wait-timeout 180`: ĐẠT;
  cơ sở dữ liệu, ứng dụng phía máy chủ và giao diện đều sẵn sàng.
- `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 smoke`: ĐẠT;
  health/liveness/readiness, OpenAPI, Swagger, `/login`, `/operations/rescue` và
  `/api/unknown` JSON 401 không phương án dự phòng HTML.
- Playwright CLI trình duyệt thật: mở trực tiếp `/operations/rescue` và reload đều tải
  SPA shell, vai trò bảo vệ đưa unauthenticated trình duyệt về `/login`; không có 404 deep định tuyến.
- `npm run build` trong giao diện Docker ảnh môi trường: ĐẠT.

Rà soát bổ sung:

- `.\mvnw.cmd clean verify`: ĐẠT, 113 kiểm thử, 0 failure/error/skip; kiểm thử tích hợp
  dùng ba PostGIS Testcontainers thật.
- Giao diện `typecheck`, 16 kiểm thử tệp / 72 kiểm thử và môi trường triển khai biên dịch: ĐẠT.
- Compose môi trường triển khai build/up/smoke: ĐẠT; backend-only `smoke -BaseUrl` cũng ĐẠT
  khi giao diện container đã dừng.

- `docker compose --env-file .env up --build -d --wait --wait-timeout 180`: ĐẠT;
