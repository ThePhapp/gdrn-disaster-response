## Contract runtime D1 đã cung cấp

Frontend gọi đúng các operation đã chốt ở P00:

| API | Mục đích |
| --- | --- |
| `GET /api/rescue-teams?page=&size=&sort=name,asc hoặc name,desc&availability=AVAILABLE` | Picker đội có thể nhận mission |
| `POST /api/rescue-missions` body `{"reportId":"...","teamId":"..."}` | Tạo và phân công mission |
| `GET /api/rescue-missions?page=&size=&sort=createdAt,desc hoặc createdAt,asc&status=...` | Danh sách điều phối |
| `GET /api/reports/{id}` | Hiển thị detail report được chọn |
| `PATCH /api/rescue-missions/{id}/status` body `{"status":"IN_PROGRESS hoặc COMPLETED"}` | Chuyển trạng thái |

D1 đã cung cấp quyền AUTHORITY cho write, citizen chỉ đọc tiến độ qua contract của S03,
V6 migration và các lỗi nghiệp vụ `TEAM_BUSY`, `REPORT_ALREADY_ASSIGNED`,
`REPORT_NOT_VERIFIED`, `DISASTER_NOT_ACTIVE`, `INVALID_TRANSITION` theo P00. Runtime
slice `rescue.json`, controller và JDBC adapter đã có trên `main` tại `e380d68`; D1
integration tests xác nhận concurrency protection. E2E UI tạo duplicate report thật và
nhận 409 `REPORT_ALREADY_ASSIGNED`, còn race hai caller được D1 RescueIT kiểm chứng.
