## Implemented

- k6 E07 write, E08 paginated read, E08 radius read and documented mixed workload;
- environment-driven base URL, credentials, VUs, duration, seed and query settings;
- JWT lifetime check covering warm-up, steady run and ramp-down;
- deterministic seed generator through E07, with a 70% dense / 30% wide location mix;
- explicit reset guard for a separately named benchmark Compose project/database;
- per-repetition raw k6, summary, seed manifest and optional Docker stats paths;
- Kaggle CPU notebook that distinguishes generator-only from server-on-Kaggle and
  reports missing Java/k6/Docker/server capability instead of assuming success.

## Measurement status at handoff

The runner is ready for smoke and 10/50/100 VU runs. The actual measurement table
must be filled only after a stable X1 commit and a disposable benchmark stack are
available. Until then, any local output is a machine-specific baseline and must not
be described as a Kaggle result or a before/after improvement.

When running, attach the complete timestamped result directory rather than copying
only percentile numbers. Include `raw.json`, `summary.json`, `run.json`, `seed.json`
when used, and `docker-stats.csv` when the collector had Docker access.

## Known limitations

- Native k6 was not assumed to be installed; the runner supports a local
  `grafana/k6` Docker image. Kaggle may not have a Docker daemon.
- CPU/RAM is sampled only when Docker container names and the Docker daemon are
  available; otherwise the report must say unavailable.
- No public DB/service/tunnel is created by the notebook or scripts.
- A benchmark credential is required, but credentials are never written to the
  notebook, manifests or Git.
- The read workloads require the generator to populate the disposable database
  before each repetition; write-only runs should start after reset.
